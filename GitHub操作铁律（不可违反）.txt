## 🔒 GitHub 操作铁律（不可违反）

**适用范围**：当且仅当任务涉及 GitHub 仓库操作时，必须且只能遵守以下全部约束。  
**违规后果**：任何一条被违反即视为严重错误，不得以任何理由豁免。

---

### 第 1 条 – 唯一仓库
所有 GitHub 操作的目标仓库固定为：  
`https://github.com/bilieebiliee1-design/SOMCP`  
**禁止**对任何其他仓库进行克隆、推送、拉取、创建 Issue/PR 或其他任何形式的操作。

---

### 第 2 条 – Token 使用
- 认证 Token **仅**通过环境变量 `GITHUB_TOKEN` 引用。
- **严禁**以任何形式获取、读取、显示或泄露该变量的实际值，包括但不限于：
  - 打印到终端或日志；
  - 回显至输出流；
  - 写入文件；
  - 拼入 URL 或请求参数；
  - 赋值给其他变量后再输出；
  - 通过调试信息、错误堆栈等方式暴露。
- 任何违反此条的行为均属严重安全违规。

---

### 第 3 条 – 签名文件绝对禁传
- 任何形式的**签名文件**（包括但不限于 `.sig`、`.asc`、`.signature` 以及文件名或内容包含 `"sign"` 字样的文件）**绝对禁止**上传、推送、提交或以任何方式传输至该 GitHub 仓库。
- **无例外、无豁免**，即使文件为空或看似无害也不得触碰。

---

### 第 4 条 – 其余操作放行
在**不违反**第 1、2、3 条的前提下，允许对该仓库执行其他合法操作，例如：
- 克隆仓库；
- 拉取最新代码；
- 推送**非签名文件**；
- 创建 Issue 或 Pull Request；
- 评论、标签管理等。

---

### 第 6 条 – 所有修改必须通过 Pull Request
任何对仓库内容的修改（包括新增、更新、删除文件或目录），**必须**通过创建 Pull Request 的方式提交，经审查合并后方可生效。  
- 禁止直接推送到默认分支（如 `main` 或 `master`）。
- 禁止绕过 PR 流程进行任何形式的直接修改。
- PR 的创建和合并需遵守仓库现有协作规范。
